# Cream Soda для Android

Сервер работает прямо на телефоне. Внутри APK есть Node.js ([Node.js for Mobile Apps](https://github.com/nodejs-mobile/nodejs-mobile) через плагин [capacitor-nodejs](https://github.com/hampoelz/Capacitor-NodeJS)), сервер Cream Soda и интерфейс. Интернет нужен только для запросов к модели.

## Что умеет лаунчер

- **«Сервер на телефоне».** Показывает три шага: «Движок распакован», «Сервер запущен», «Открываю интерфейс…». Когда сервер готов, интерфейс открывается сам. Если из интерфейса нажать «Назад» до конца, вы вернётесь в лаунчер, а сервер продолжит работать.
- **«Работать в фоне».** Запускает foreground-службу с уведомлением «Сервер работает», чтобы Android не выгружал сервер, пока вы в другом приложении. На Android 13+ при первом включении система попросит разрешение на уведомления.
- **«Не давать экрану гаснуть».** Экран не гаснет, пока открыто приложение. Пригодится при долгой генерации.
- **«Подключиться к ПК».** Сканирует QR-код из лаунчера на компьютере (сканер Google, разрешение на камеру не нужно) и открывает интерфейс, который работает на ПК. Если сканера нет, адрес вида `192.168.1.12:8000` можно ввести вручную.
- **Обновления · Бэкап · Логи.** «Обновления» открывают страницу релизов. «Бэкап» сохраняет zip в «Загрузки/Cream Soda». «Логи» показывают журнал сервера.

Экспорт из интерфейса (карточки PNG/JSON, чаты, пресеты, бэкап из настроек) тоже сохраняется в «Загрузки/Cream Soda». WebView на Android сам не умеет скачивать файлы, поэтому это делает `MainActivity` через `window.CreamSodaAndroid`.

## Сборка APK

Понадобятся Node.js 20+, JDK 21 и Android SDK (проще всего поставить Android Studio).

```bash
# 1. В корне репозитория: зависимости и сборка интерфейса
npm install
npm run build

# 2. Здесь, в launcher/android
cd launcher/android
npm install
npm run add        # первый раз: создаёт android/, иконки, нативные настройки
npm run apk        # android/app/build/outputs/apk/debug/*.apk
```

Дальше после изменений достаточно `npm run sync` (или сразу `npm run apk`). Чтобы открыть проект в Android Studio, выполните `npm run open`.

Что делают скрипты:

| Скрипт | Что делает |
| --- | --- |
| `npm run build` | Собирает экран лаунчера (`src/` → `www/`). Собирает Node-проект для телефона в `www/nodejs/`: сервер, собранный интерфейс, продакшн-зависимости и `node/main.cjs`. |
| `npm run add` | `cap add android` + иконки и заставка из `resources/` + `scripts/patch-android.mjs`. |
| `npm run sync` | Пересобирает и копирует всё в `android/`, затем снова применяет нативные настройки. |
| `scripts/patch-plugins.mjs` | Заменяет `CapacitorNodeJS.java` в плагине capacitor-nodejs исправленной копией из `native/capacitor-nodejs/`. Запускается после `npm install` и перед каждой сборкой. На другой версии плагина останавливается с ошибкой, а не теряет исправление молча. |
| `scripts/patch-android.mjs` | Вносит в манифест разрешение на HTTP к `127.0.0.1`, foreground-службу (`specialUse`), уведомления и модуль сканера QR. Кладёт `native/MainActivity.java`, иконку уведомления и `native/cream-soda.gradle` (версия, APK по архитектурам, подпись). Повторный запуск ничего не ломает. |

Папка `android/` генерируется и в git не хранится. Всё нативное лежит в `native/` и `scripts/patch-android.mjs`.

Собирается отдельный APK для каждого типа процессора (только libnode занимает около 50 МБ на тип) и один универсальный:

| Файл | Для чего |
| --- | --- |
| `*-arm64-v8a-*.apk` | почти все телефоны последних лет |
| `*-armeabi-v7a-*.apk` | старые 32-битные телефоны |
| `*-x86_64-*.apk` | эмуляторы и редкие x86-устройства |
| `*-universal-*.apk` | подходит всем, но весит около 200 МБ |

Версию приложения (`versionName` и `versionCode`) скрипт берёт из корневого `package.json`.

### Релизная сборка и подпись

`npm run apk:release` подписывает APK ключом из `keystore.properties` (файл и ключ в git не попадают):

```properties
storeFile=cream-soda-release.jks
storePassword=…
keyAlias=cream-soda
keyPassword=…
```

Создать ключ можно так: `keytool -genkeypair -keystore cream-soda-release.jks -storetype PKCS12 -alias cream-soda -keyalg RSA -keysize 4096 -validity 36500`. **Храните ключ и пароль.** Android ставит обновление поверх только с той же подписью. Если подписать новую версию другим ключом, приложение придётся удалить, и данные в нём пропадут. Перед этим сделайте бэкап.

Если `repo.maven.apache.org` отвечает 429 (Too Many Requests), подключите зеркало Maven Central от Google через init-скрипт Gradle:

```groovy
// ~/.gradle/init.d/maven-mirror.gradle
def MIRROR = 'https://maven-central.storage-download.googleapis.com/maven2/'
beforeSettings { settings -> settings.pluginManagement.repositories { maven { url MIRROR } } }
allprojects {
    buildscript.repositories { maven { url MIRROR } }
    repositories { maven { url MIRROR } }
}
```

## Как это устроено

```
src/            экран лаунчера (по макету), плагины Capacitor вызываются из src/native.js
node/main.cjs   точка входа Node.js на телефоне: запускает сервер и общается с экраном через модуль bridge
native/         MainActivity (сохранение файлов), иконка уведомления, настройки Gradle
resources/      исходники иконки и заставки для @capacitor/assets
scripts/        prepare-node.mjs (www/nodejs) и patch-android.mjs
```

Экран и Node.js обмениваются сообщениями через канал `bridge`:

- экран → Node: `hello`, `start {port}`, `logs`, `backup`;
- Node → экран: `status {stage, url, port, error}`, `logs`, `backup {ok, path, name}`.

Данные лежат в личной папке приложения (`getDataPath()/cream-soda`), поэтому при обновлении APK они сохраняются. Сервер слушает только `127.0.0.1`.

## Если сервер не запускается

Лаунчер показывает, на каком шаге остановился запуск:

| Что видно | Причина и что делать |
| --- | --- |
| «Движок не запустился» через полторы минуты | Node.js не распаковался из APK, чаще всего из-за нехватки памяти телефона. Освободите место, закройте приложение полностью (смахните из недавних) и откройте снова. |
| «Node.js запущен, но не отвечает» | Скрипт сервера упал при загрузке. Нужен лог: `adb logcat -s NodeJS-Engine` (подробнее ниже). |
| «Сервер не запустился» с текстом ошибки | Ошибку вернул сам сервер, её текст в лаунчере. Кнопка «Попробовать снова» перезапустит его. |
| Порт 8000 занят (например, в Termux работает SillyTavern) | Не ошибка: сервер сам займёт следующий свободный порт. |

Подробный лог Node.js можно снять с подключённого телефона: `adb logcat -s NodeJS-Engine Capacitor/CapacitorNodeJS Capacitor/Console`. Когда сервер уже работает, его журнал есть в «Логи» внизу лаунчера.

В плагине capacitor-nodejs исправлена ошибка, из-за которой сервер не поднимался при повторном открытии приложения (`native/capacitor-nodejs/CapacitorNodeJS.java`). В исходном плагине флаг «движок запущен» хранился в объекте плагина, а не в процессе. Android пересоздаёт окно приложения, пока процесс жив: после «Назад» на Android 11 и старше, после смены размера шрифта, при нехватке памяти. Процесс при этом держит включённая по умолчанию фоновая служба. Плагин запускал Node.js второй раз в том же процессе, а это не поддерживается: приложение падало или зависало на «Распаковываю движок…». Теперь новое окно подключается к уже работающему серверу. Заодно Node-проект копируется из APK только после установки или обновления, а не при каждом запуске (около 1300 файлов).

## Ограничения

- Node.js for Mobile Apps основан на Node 18.20, а у этой ветки Node закончилась поддержка. Сервер проверен на Node 18.20.8 и работает. В README плагина capacitor-nodejs перечислены оговорки по безопасности этого рантайма, прочитайте их перед публикацией сборки.
- В рантайме нет модуля `Intl` (ICU). Сервер это учитывает. Интерфейс работает в WebView, а там ICU есть.
- `child_process` на телефоне недоступен, поэтому установка расширений через git работает только на ПК. Расширения можно поставить на ПК и перенести бэкапом.
- APK собирается (Capacitor 8, compileSdk 36, AGP 8.13, JDK 21). На реальном устройстве и в эмуляторе его не запускали: в среде сборки не было KVM. Проверено другое: экран лаунчера в браузере с заглушками плагинов, Node-часть на Node 18 и 20 с заглушкой `bridge`, содержимое APK (манифест, подпись, libnode, Node-проект, `MainActivity`).
